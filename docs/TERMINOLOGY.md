# Project Terminology

This document defines the official terminology used throughout the project. All documentation, code, APIs, database schemas, prompts and future development must follow these definitions.

---

# Organization

The highest-level entity within the platform.
An Organization owns Projects, Members, Roles and global settings.

Example:
```
ESPN
BBC
OpenAI
```

---

# Project

A collaborative production initiative belonging to a single Organization.
Projects contain Stations, Assets, Members and Activities.

Example:
```
World Cup Coverage
Product Launch
Summer Campaign
```

---

# Station

A functional production area inside a Project.
Stations organize members, permissions and assets around a specific workflow.

Examples:
- Writing Station
- Image Station
- Approval Station
- Publishing Station
- Asset Library

Stations are independent from user Roles.

---

# Asset

The core object of the platform.
Everything created inside the system is considered an Asset.

Examples:
- Text document
- Blog
- Press Release
- Image
- Generated Image
- LinkedIn Post
- Email Campaign
- Promotional Copy

Assets belong to exactly one Station.

---

# Parent Asset

The original source Asset used to generate derivative content.

Example:
```
Master Script

↓

Blog

↓

LinkedIn

↓

Twitter
```

---

# Child Asset

An independently stored Asset derived from a Parent Asset.
Child Assets remain permanently linked to the Parent through Version Tracking.

---

# Version Tracking

An immutable history of Asset snapshots.
Unlike Git Version Control, Version Tracking stores complete Asset states after each modification.

Properties:
- Append-only
- Immutable
- Snapshot-based
- No merge conflicts
- No branching

---

# Activity

An immutable audit event generated by the system.
Activities record actions but never store Asset content.

Examples:
- Login
- Asset Created
- Image Generated
- Approval
- Assignment
- Escalation

---

# Job

A single asynchronous AI task.

Examples:

- Text Generation
- Image Generation
- Content Atomization
- Image Upscaling

Every Job receives a unique task_id.

---

# Queue

The in-memory scheduler responsible for executing AI Jobs.
Current implementation:
asyncio.PriorityQueue

---

# Scheduler

The worker responsible for selecting and executing queued Jobs according to priority.

---

# Prompt Enrichment

The preprocessing stage where Gemma enhances user prompts before image generation.

Pipeline:

User Prompt

↓

Gemma

↓

Enhanced Prompt

↓

ComfyUI

---

# Content Atomization

The process of generating multiple independent child Assets from one Parent Asset.

Example:

```
Parent

↓

Blog

↓

LinkedIn

↓

Instagram

↓

Email

↓

Press Release
```

---

# AI Pipeline

The complete processing flow for AI requests.

Text:

User → Queue → Gemma → Response

Image:

User → Gemma → ComfyUI → Base64 → Frontend

---

# Approval Task

A review request assigned to a Reviewer or Manager.
Approval Tasks support automatic escalation after configurable deadlines.

---

# Auto Escalation

The automated reassignment of overdue Approval Tasks.

Example:

Reviewer

↓

Timeout

↓

Manager

↓

Timeout

↓

Administrator

---

# Role

A predefined collection of Permissions.

Examples:

Administrator

Manager

Editor

Reviewer

Publisher

Viewer

---

# Permission

A single action allowed inside the platform.

Examples:

asset.read

asset.write

image.generate

approval.review

logs.view

---

# Metadata

Additional structured information stored alongside Assets.

Examples:

- Created By
- Tags
- Prompt
- Generation Parameters
- Model
- Timestamp

---

# Soft Delete

Logical deletion where data remains stored but hidden from normal users.

Implemented using:

deleted_at

instead of

is_deleted

---

# Repository

The only layer permitted to communicate directly with PostgreSQL.
No SQL may exist outside Repository classes.

---

# Service

Business logic layer responsible for coordinating repositories, AI engines and API endpoints.

---

# API

The FastAPI backend exposed to the frontend.
The frontend never communicates directly with AI engines.

---

# Frontend

The React application responsible only for presentation and user interaction.
Business logic never resides inside React components.

---

# AI Engines

External generation services.

Current engines:

Gemma 2B (Prompt Enrichment)

ComfyUI (Image Generation)

Future:

Video Generation

Speech

OCR

Translation

---

# Local Storage

SSD-based storage for generated assets.
PostgreSQL stores metadata only.
Images are referenced using file paths.

---
